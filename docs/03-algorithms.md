# 03 · 性能与算法优化

## 0. 性能目标（验收基准）

| 指标 | 目标 | 测试文档 |
| --- | --- | --- |
| 按键 → 画面更新 | p95 < 16ms | 10,000 块 |
| 打开文档 → 首屏可读 | < 200ms | 10,000 块 / 2MB |
| 打开文档 → 可编辑 | < 500ms | 同上 |
| 保存（序列化） | < 50ms，且不阻塞主线程 | 同上 |
| 运行时加载器体积 | < 8KB gzip | — |
| 完整编辑器体积 | < 150KB gzip（不含图表等按需依赖） | — |

基准测试放在 `tests/bench/`，CI 中跑并对比上一次结果，退化 > 10% 视为失败。

## 1. 解析：受限子集的单遍流式解析 O(n)

**问题**：通用 HTML 解析（DOMParser / parse5）要构建完整 DOM 树，对大文件慢且需要主线程或 jsdom。

**方案**：
- `core` 自带一个**手写状态机分词器**，只识别规范内的标签、属性和实体，单遍扫描直接产出 `Block`，不构建中间 DOM；
- 遇到规范外的片段，记录 `[start, end)` 字节区间作为 `HtmlBlock`，原文切片保留，首次编辑时才建立其内部区间索引；
- 任意 HTML 的保真编辑使用**源码区间补丁**算法，见 [06-import.md §2](06-import.md)；
- 组件 JSON 延迟解析：只记录区间，首次访问 `props` 时才 `JSON.parse`（lazy getter）。

**分段/并行**：顶层块之间天然有边界（`data-eh` 属性），大文件可先做一次快速扫描找到块边界，再把块分片交给 Worker 并行解析。

**首屏优先**：先解析前 N 个块（填满视口）并渲染，其余在 `requestIdleCallback` 中继续。

## 2. 增量渲染：块级哈希 + keyed diff

**问题**：每次修改都整体重渲染文档，在长文档中不可接受；通用虚拟 DOM 对整棵树 diff 也是 O(n)。

**方案**：
- 每个块维护内容哈希 `hash`（行内内容用 **FNV-1a / xxHash32**，组件用 props 的规范化 JSON 哈希）；
- 事务产出 `dirtySet: Set<BlockId>` —— 渲染器**只访问 dirty 块**，复杂度 O(改动块数) 而不是 O(文档块数)；
- 块顺序变化（插入、删除、移动）用基于 key 的列表 diff：对旧/新序列求 **LIS（最长递增子序列，O(n log n)）**，只移动不在 LIS 中的节点，DOM 移动次数最少（Vue 3 / Inferno 同款算法）；
- 块内行内内容：对 InlineNode 数组做首尾公共前后缀裁剪后再 patch，绝大多数打字只触及一个文本节点。

## 3. 长文档：虚拟化 + 懒渲染

- **组件块懒渲染**：`IntersectionObserver` 监听，进入视口（含 1 屏预加载距离）才加载依赖并渲染交互版本，此前显示降级内容；离开视口足够远时可销毁交互实例只留降级 DOM；
- **块虚拟化**（块数 > 2000 时启用）：只挂载视口附近的块，其余用占位高度；
  - 块高度用**前缀和数组 + Fenwick 树（树状数组）**维护：单块高度变化 O(log n) 更新，滚动位置 → 块索引 O(log n) 查找；
  - 未测量的块用同类型块的平均高度估算，测量后修正并做滚动锚定（避免跳动）；
- 选区或 IME 组合中的块**永不被虚拟化回收**。

## 4. 事务、撤销重做

- 操作日志（Op log）+ 可逆操作：撤销 = 应用 `invert(tx)`，无需存快照，内存 O(改动量)；
- **输入合并**：同一块内、时间间隔 < 500ms、类型相同的连续 `insertText` 合并为一个历史项；遇到空格/标点/换块时断开（与主流编辑器习惯一致）；
- 位置映射（Mapping）：撤销时，后续操作对位置的影响通过 `map(pos)` 逐步变换，保证撤销的是"那段文字"而不是"那个偏移"；
- 历史上限按操作数和内存双阈值裁剪；
- 每 N 次事务做一次**轻量快照**（只记录块哈希表），用于快速校验与崩溃恢复。

## 5. 保存：增量序列化 + 后台写回

- **块级序列化缓存**：`Map<BlockId, {hash, html}>`；保存时只重新序列化 hash 变化的块，其余直接拼接缓存字符串 → 典型保存 O(改动块)；
- 序列化在 **Web Worker** 中进行（`core` 无 DOM 依赖使之成为可能），主线程只传递变更块；
- 防抖自动保存：最后一次输入后 800ms，或距上次保存超过 5s 时强制保存（throttle + debounce 组合）；
- 写入前比较文件 `lastModified`，若外部（git、同步盘）改过则进入**三方合并**流程（见 §6）；
- 写入采用"写临时文件 → 重命名"（宿主支持时）防止写一半崩溃导致损坏。

## 6. 外部修改与合并

- 以块为单位做三方合并：`base`（上次保存）/ `mine`（当前编辑）/ `theirs`（磁盘新版）；
- 块 ID 对齐 → 只在两边都改了的块上产生冲突；同块内文本冲突用 **Myers diff（O(ND)）** 尝试行内合并，失败则保留两个版本并标记冲突块让用户选择；
- 为将来协作预留：Op 设计成可以映射到 CRDT（如 Yjs 的 `Y.Array<Y.Map>` + `Y.Text`），v1 不实现。

## 7. 搜索、双链与斜杠菜单

- **斜杠菜单 / 命令面板**：组件名不多（< 200），用带权重的**子序列模糊匹配**（类 fzf 打分：连续命中、词首命中加分），O(候选数 × 查询长度)，输入时无感；
- **全库搜索**（apps/web、插件）：增量维护**倒排索引**，中文用 n-gram（bigram）分词、英文按词 + 前缀；文件变动时只重建该文件的条目；索引持久化到 IndexedDB；
- **双链 `[[note#block]]`**：维护反向链接表 `Map<target, Set<source>>`，随文件增量更新。

## 8. 渲染缓存

- 组件降级内容（如 Mermaid SVG、图表 SVG、KaTeX HTML）以 `hash(type + 规范化props + 主题)` 为 key 缓存（内存 LRU + IndexedDB），重复打开或回滚时直接命中；
- 重依赖（图表库、Mermaid、KaTeX）**按需动态 import**，并在空闲时预取文档中已出现的类型。

## 9. 输入路径的微优化清单

- 输入事件内只做"生成 Op → apply → 标记 dirty"，DOM patch 合并到同一个 `requestAnimationFrame`；
- 禁止在输入路径中读取布局（`offsetHeight` 等）造成强制同步布局；高度测量统一用 `ResizeObserver` 异步回调；
- 文本块使用 `content-visibility: auto` + `contain-intrinsic-size` 作为虚拟化前的廉价兜底；
- IME 组合期间（`compositionstart`→`end`）暂停模型同步，结束时一次性提交，避免中文输入抖动。

## 10. 正确性保障（让优化不出错）

- **往返属性测试**（fast-check）：随机生成 Doc → serialize → parse → 等价；serialize 幂等；
- **增量 = 全量**：随机事务序列下，增量渲染结果的 DOM 与从头渲染的 DOM 必须一致（测试中对比 `innerHTML` 规范化结果）；
- 增量序列化结果与全量序列化逐字节一致；
- 撤销 N 步再重做 N 步，文档哈希不变。
