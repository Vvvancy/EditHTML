# 00 · 愿景与动机

## 1. 问题

在 Obsidian 等 Markdown 笔记工具里记笔记时，**表现形式太单一**：基本只有标题、正文、列表、代码、图片几种。想要更丰富的呈现——图表、多栏布局、标签页、可折叠区、交互演示、自定义配色——Markdown 要么不支持，要么只能靠各家插件的私有语法，换个工具就失效。

于是转而用 HTML / 网站（HTML + CSS + JavaScript）作为阅读载体：表现力几乎无上限，图表、交互都能做。但网站的问题是**编辑太重**：

- 想改一个字，要回到源码（"后台"）里找到对应位置再改；
- 渲染后的页面是只读的，无法像 Markdown 编辑器那样"所见即所改"；
- 手写 HTML 的结构噪音大，记笔记的速度远不如 Markdown。

## 2. 目标

做一个介于两者之间的东西，融合各自长处：

| 来自 Markdown | 来自 HTML / 网站 |
| --- | --- |
| 随时修改、即时生效 | 展示效果好、样式自由 |
| 输入快（快捷语法） | 支持图表、交互组件、脚本 |
| 纯文本友好、可 diff、可 git 管理 | 任何浏览器都能直接打开 |
| 渲染快 | 可以当成一个"网站"来分享 |

核心体验：**打开一个笔记 = 打开一个漂亮的网页；在这个网页上直接点、直接改、直接存。**

## 3. 目标用户

1. 用 Markdown 记笔记、但嫌表现力不够的人（首要用户，即作者本人）；
2. 习惯用 HTML 做读书笔记、知识卡片、学习页面的人；
3. 想把笔记直接当作静态页面分享的人。

## 4. 设计原则

1. **文件即网页**：`.ehtml` 文件不依赖编辑器也能完整阅读。编辑器不在时，退化为一个普通的静态网页，而不是一堆看不懂的标记。
2. **就地编辑**：所有内容（包括图表数据、组件配置）都能在渲染页面上编辑；源码视图是可选的高级入口，而不是必经之路。
3. **Markdown 手感**：输入规则兼容常见 Markdown 习惯；可以从 `.md` 无损导入，也可以导出回 `.md`（富组件降级为代码块/图片）。
4. **块是一等公民**：文档 = 有序的块序列。块分为"文本块"（段落、标题、列表……）和"组件块"（图表、标签页、脚本……），组件块可扩展。
5. **稳定的序列化**：同样的内容永远保存成同样的字节；只改一个字，git diff 只出现一行。
6. **快**：输入延迟 < 16ms（一帧），万块级长文档打开 < 500ms（见 [03-algorithms.md](03-algorithms.md)）。
7. **安全**：笔记中的自定义脚本默认运行在沙箱中，不能读写宿主页面和本地文件。

## 5. 非目标（至少 v1 不做）

- 不做多人实时协作（但数据结构为将来接 CRDT 留口子）；
- 不做通用建站工具 / 页面搭建器（不追求像 Webflow 那样任意拖拽布局）；
- 不做云同步服务（文件就是本地文件，同步交给 git / 网盘 / Obsidian Sync）；
- 不追求兼容任意第三方 HTML 的就地编辑（只保证 `.ehtml` 规范内的内容可编辑，规范外内容原样保留、只读）。

## 6. 成功标准

- 能用它替代 Obsidian 完成日常笔记，并且至少 30% 的笔记用到了 Markdown 做不到的组件；
- 任意 `.ehtml` 文件在无网络、无编辑器的浏览器中正常显示；
- `.md → .ehtml → .md` 往返对纯 Markdown 内容无损。
