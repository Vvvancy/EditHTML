# 05 · 待决策问题

按影响大小排序。决定后把结论写回对应文档，并在此处标记 ✅。

1. ✅ **编辑器底座**：ProseMirror（路线 A）还是自研块层（路线 B）？
   **结论（2026-11-22）：采用路线 A（ProseMirror）。** `core` 保持独立模型，PM 只作为"视图 + 输入层"，通过 `editor/src/pm/` 适配层双向映射；组件块用 NodeView。M3 性能基准（T3.5/T3.7）若不达标，再评估把块层替换为路线 B，`core` 不受影响。已写回 02 §5。
2. **运行时是否内联进每个文件**：内联则完全离线可编辑，但每个文件多 ~8KB 且升级运行时需改所有文件；外链则相反。
   建议：默认外链 + 本地缓存；导出"分享版"时内联。也可支持"笔记库级"共享运行时文件 `./.ehtml/runtime.js`。
3. **文件扩展名**：`.ehtml` 还是 `.html`？`.html` 系统默认用浏览器打开更方便，`.ehtml` 便于工具识别。
   建议：规范以 `data-eh-version` 识别，两种扩展名都支持，默认 `.eh.html`（兼顾两者）。
4. **图表库**：ECharts（中文生态好、交互强、体积大）vs Vega-Lite（声明式、数据驱动、可导出 SVG）。
5. **容器块嵌套深度上限**：建议 4。
6. **块 ID 是否写进 EHMD 源码**：写入可稳定引用但影响可读性；建议只在被引用的块上显示 `^id`。
7. **数学公式行内语法**：`$...$`（与 Obsidian 一致）——是否会与普通美元符号冲突，需定义转义规则。
8. **自定义脚本的信任粒度**：按文件信任 / 按笔记库信任 / 按组件哈希信任。
9. **项目名称**：EditHTML 作为仓库名，格式与产品是否另起名字？
10. **列表项只能放行内内容**（T1.1 模型）：`ol[start]`/`reversed`、列表项内的多段落/代码块/图片无法表达。可选：给 `li` 加 `start` 属性；或允许"列表项容器块"。
11. **引用块只有单段**：Markdown 的多段/嵌套引用无法无损往返（目前解析为外来块）。可选：把 `quote` 做成容器块，或导入时转为 `callout`。
12. **段落内的 `<img>`**：按"白名单外行内元素去壳"规则会被删掉。建议加入行内白名单（`img[src][alt]`）或作为 `atom`。
13. **`span[data-eh-inline]` 的载荷格式**：行内公式/双链/标签/颜色高亮各自的属性与文本约定尚未定义。
14. **未知组件缺少 JSON**：目前补 `{}`，导致此类文件首次保存会改变字节（fixture 15 的 u3）。
15. **EHMD 细节**：容器块语法（fixtures 中暂用 `:::callout 标题 {#id kind=info}`）、列表/表格/hr 的 ID 位置、Obsidian `> [!note]` / mermaid 代码块 / `$$` 是否自动转组件。
16. **链接协议白名单**：除 `javascript:` 外，`vbscript:`、`data:` 链接是否也剔除（建议：是）。
17. **其他边界**：Unicode 规范化、CRLF 是否统一为 LF、空段落是否保留、块 ID 字符集是否放宽、`#eh-meta` 缺失时 meta 的默认值。

> 10–17 来自 T0.3 / T1.2 / T1.3 实现过程中发现的规范空白，详见 `tests/fixtures/README.md`。
